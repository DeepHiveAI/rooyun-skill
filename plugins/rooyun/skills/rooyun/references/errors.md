# 错误处理详版

> RooYun Skill 参考文档（从 SKILL.md 拆出）· 主文件：[SKILL.md](../SKILL.md)
> **何时读**：撞上非 2xx、任务失败、或与浏览器同时编辑起冲突时

## 错误处理指引

**一律按 `error.code` 分支，不要按 HTTP 状态码，更不要按 `message` 文案**（文案随时会改措辞）。
`dj.mjs` 失败时 stdout 仍是完整信封，stderr 给人读提示。

`dj.mjs` 退出码：`0` 成功 / 任务 succeeded ｜ `1` 用法或配置错误 ｜
`2` API 业务错误（`canvas lint` 另用它表示「体检有 error 级 finding」，处置一致：别往下走）｜
`3` 402（余额或限额）｜ `4` 429 ｜ `5` 网络异常 ｜ `6` `--watch` 超时（任务仍在跑，不是失败）｜
`7` 任务终态但非 succeeded。

### 慢端点会先回 HTTP 200 再报结果（心跳保活）

`analyze/storyboard` 拆一集分镜要 2–15 分钟。为了不被中间层按「空闲超时」掐断，
服务端在等待期会周期性吐 JSON 合法的空白字节保活——**响应头因此提前发出，
HTTP 状态码恒为 200**，真实状态码改放在信封的 `meta.httpStatus`。

对你没有影响：判成败本来就该看 `ok` 与 `error.code`（上面第一条纪律），
`dj.mjs` 也已按 `meta.httpStatus` 还原退出码。只有绕开 `dj.mjs` 直接 curl 的脚本
需要注意：**别只看 HTTP 状态码**，且别设「总耗时」型超时——要设也设成
「多久没收到字节」（`dj.mjs --request-timeout` 就是这个语义，默认 120 秒）。

### 两个 402 千万别合并处理

| code | 真实含义 | 该怎么办 |
|---|---|---|
| `insufficient_credits` | **账户余额**空了（或只剩不覆盖该模型的赠送积分） | 把两条路摆给用户：**换 MiniMax H3**（更便宜、赠送积分可用，重新报价）或**去网页端充值**（纪律 12）。别自己换模型盲重试 |
| `token_limit_exceeded` | **这枚令牌**的消费限额用尽（账户里可能钱还多得很） | 请用户去 `/profile#api` 调额度或换一枚令牌。**绝不能引导用户充值**——充了照样跑不动 |

### 其余高频码

| code | HTTP | 处置 |
|---|---|---|
| `creator_upstream_failed` | 502 | 抖音那边没取到（多半是播放地址过期或临时频控）。退避 1–2 分钟重试；**连续失败别再密集打**——那是全站共享的出口 |
| `archive_limit_reached` | 409 | 未过期的转存原片满了。没有参数可改、重试也没用——等最早一份过保留期后名额自动回收 |
| `insufficient_scope` | 403 | 令牌缺 scope，请用户重建一枚勾上对应权限的。不要重试 |
| `radar_not_enabled` | 403 | 账号没开通「选题雷达」。**与 scope 无关——重建令牌不解决任何问题**，要管理员给账号开通。雷达 / 简报 / 文案库三个域共用这一个权益，任一域被拒都是这个码 |
| `token_revoked` / `token_expired` / `token_invalid` | 401 | 请用户重新签发并更新环境变量 |
| `invalid_request` | 400 | 参数不合法，整批 fail fast，没有半批落盘。改参数，别重试 |
| `not_found` | 404 | 不存在**或不属于本令牌**（刻意不区分，防资源探测） |
| `rate_limited` | 429 | 退避后重试。下载端点上它还有第二种成因：**在途签名授权预算（512 MiB/令牌）被并发拉大件占满**，此时带 `meta.retryAfterSeconds`（秒），等一等或把并发降下来即可——别当成配额耗尽去换令牌 |
| `version_mismatch` | 409 | 你给的 `ifVersion` 已过期 → 重读 `structure` 拿新 version 再写。**盲目重试无意义** |
| `version_conflict` | 409 | CAS 重试 3 轮仍冲突（多半是用户正在浏览器里编辑）→ 重读结构后重试 |
| `ops_failed` | 422 | 参数合法但执行不成立；整批未落盘，看 `meta.results` 逐条定位 |
| `node_limit_exceeded` / `doc_too_large` | 422 | 单画布 5000 节点 / 32 MiB 上限。**不是抖动**，请拆到多张画布 |
| `document_nodes_dropped` | 422 | 云端文档过不了无损读护栏。**不要重试**，请用户在浏览器里打开确认 |
| `model_unsupported` | 400 | 模型不存在/下架/不支持该能力 → `models --capability <cap>` 重挑。带 `referenceVideoAssetIds` 时还有一种成因：**该模型未声明参考视频能力**（目录不投影这条细分能力）→ 换支持参考视频的 `ref2v` 模型 |
| `asset_unresolved` | 422 | 素材引用解析失败（不属于你 / 未同步 / 签名失败），或 `v2a` / `blockout` 源片与参考视频的**时长解析不出**（按秒计价的路不猜时长）。重试解决不了，**换模型也解决不了**——去查素材 |
| `mask_unsupported` | 422 | 该模型所在**渠道**承载不了局部重绘蒙版。与上一行处置相反：**换个图片模型就好**，素材没问题 |
| `node_not_found` | 404 | 定向落卡的画布或节点不存在。**未提交任何任务**，重试安全 |
| `canvas_busy` | 409 | 画布正被并发修改，标记生成中失败。**未提交任何任务**，重读结构后重试 |
| `node_busy` | 409 | 目标卡上已有在跑的生成（用户自己发起的，或你上一笔）。**未提交任何任务**。与 `canvas_busy` 不同，**重读结构没用**——等它跑完，或换一张卡。别写成同一条重试分支，会死循环 |
| `reference_job_active` | 409 | 你（这个账号）的拆解队列满了：1 条在跑 + 3 条排队。**未提交、没有扣费**。`meta.activeJobId` 是在跑的那条、`meta.queued` 是排队数：`dj reference-analysis <activeJobId>` 等它到终态（5–15 分钟）后再发。**不是参数错误**，别放弃也别换令牌绕 |
| `cancel_unsupported` | 409 | 该任务由上游渠道执行，没有取消通道。诚实告诉用户：等它自然结束，钱照付 |
| `asset_not_in_cloud` | 404 | 不是 id 错了，是东西没上云 → 请用户在原设备导出 |
| `download_quota_exceeded` | 429 | 令牌当日下载配额 5 GiB 耗尽（UTC 00:00 重置）。与上面那种 429 不同：**这个等不来**，只能等次日或换令牌。302 的响应头 `x-download-quota-remaining`（当日余额）与 `x-download-grant-remaining`（在途预算余额）可用来提前节流 |
| `upstream_rejected` | 4xx/5xx | 上游拒绝或暂不可用，`message` 已脱敏 |
| `llm_upstream_failed` | 502 | 分析端点的上游挂了。**已自动退款**，可直接重试 |
| `llm_empty_output` | 502 | 上游正常收尾却没吐字。**已自动退款**，可直接重试 |
| `llm_unparsable_output` | 502 | 有输出但结构不对。**已计费不退款**（token 真烧了），通常重试即可——但要知道这一次已经付过钱 |
| `llm_output_truncated` | 502 | 产物撞输出上限被截断，残缺。**已计费不退款**，且**重试徒劳**（同样的输入与上限必然截在同一处）。拆短剧本分批处理，或换输出上限更高的模型 |
| `session_consumed` | 409 | 编辑会话已被用掉（用户已提交过），撤销不了。改为 `edit-session status` 取回 `result` 里的蒙版继续流程 |
| `conversation_busy` | 409 | 多轮会话正被另一个写方占用（`meta.lockedBy`：`api` = 上一轮还没跑完 / `web` = 用户正在网页端写同一段）。按 `meta.retryAfterSeconds` 退避，**同一个 `conversationId` + 同一个 `requestId` 原样重发**。这一轮还没扣钱；**别新建会话、别并发再打一轮**（纪律 13） |
| `agent_not_conversational` | 400 | 该 Agent 开不了会话（编排型，要在画布里跑）。`dj agents` 里挑 `conversational: true` 的，别换个 id 盲试 |
| `agent_unknown` | 400 | `agentId` 不在目录里、已下线，或这段会话没绑定 Agent。先 `dj agents` 抄准 id——会话建好后 Agent **不可改**，换 Agent = 新建一段会话 |
| `turn_incomplete` | 502 | 一轮跑完了却没能落库成消息。用**同一个 `requestId`** 重发（幂等，不重复扣费）；仍失败就 `dj chat history` 看会话停在哪一 `seq` |
| `service_unavailable` | 503 | 依赖暂不可用（含模型未配价），可重试 |

### 任务终态的三个坑

- `landedTo: "assets"` **不算失败**：目标卡片被删了，产物真的做出来了，从 `/v1/assets` 照样取。
- `landedTo: null` 且非终态 = 还没落，下次轮询自动重试，别当异常。
- **`succeeded` 但没有 `assetId`**：任务成功了但产物代取转存失败。**钱已经花了**。
  去 `assets list` 里按时间找一找，**别当成失败直接重抽**（那是第二次付钱）。

> ✅ **这两种情况都能自己收尾**：用 `attachAsset` 把产物绑回画布——
> 目标卡还在就直接绑，卡被删了就先 `createCard` 建一张同类型的空卡再绑。
> **绝对不要重新生成一次**，那是让用户第二次付钱。
>
> ```json
> { "ops": [
>   { "op": "createCard",  "params": { "kind": "image", "title": "镜3 推近" } },
>   { "op": "attachAsset", "params": { "nodeId": "<上一批返回的 id>", "assetId": "<64 位 hex>" } }
> ] }
> ```
>
> 建卡与绑定必须**分两批**：节点 id 由服务端生成，同一批里引用不到刚建的卡。
> `attachAsset` 只接受**空卡**（已有产物 / 版本链 / 在途任务一律 `card_not_empty`）——
> 覆盖会让原产物脱离资产引用集、被回收误删，所以这个口子不开；正解永远是「新建一张再绑」。

### 取消的诚实语义

三态看 `cancelState`：`stopped` = 真停住（还在排队、算力尚未取走），冻结积分全额退回；
`recorded` = 已在跑，取消意向在案——优先按自然终态结算，**若约 10 分钟内仍无终态，
服务端主动收敛为 canceled 并全额退回**（继续轮询 GET 必能等到终态与 `chargedCredits`，
不会永远挂着）；`already_final` = 早已终态，幂等空操作。
如实告诉用户「已记录，若任务正常跑完这一单还是要付钱」，别让他以为必然省下了。

## 和浏览器同时编辑会发生什么（诚实说明）

不会损坏数据。用户开着画布时，浏览器会**自己发现**你的写入，通常不需要刷新页面。

| 情形 | 行为 |
|---|---|
| API 写入时云端版本已被推进 | 自动「重读 → 重放」最多 3 轮；仍冲突 `409 version_conflict` |
| 你给了 `ifVersion` 且不匹配 | 不重试，直接 `409 version_mismatch` |
| 用户开着这张画布、本地**没有**未同步改动 | 15–25 秒内**原地收敛**：新卡自己出现，提示「Agent 已更新画布」，**不刷新页面**、视口不动、资产自动补齐 |
| 用户开着这张画布、本地**有**未同步改动 | 顶部出一条**非模态横幅**提示云端有新变更（会点名是哪枚 API 令牌写的），带「处理 / 稍后」按钮，不打断他编辑；他把本地改动同步掉之后下一轮自动收敛 |
| 用户随后在浏览器里保存 | 上面两条已经把大部分冲突提前化解掉了；真撞上冲突才弹裁决对话框，由用户选保留哪边（对话框同样显示写方是哪枚令牌） |
| 你对某张卡发起了定向生成 | 那张卡在浏览器里显示为「云端生成中」只读态；任务终态后自动恢复可编辑 |

**发现机制只覆盖用户此刻正开着的那一张画布。** 用户不在画布页、你写的是别的画布、
或者你**新建**了一张画布时，他仍然要切过去/刷新才看得到。

所以纪律 2 才是纪律：**优先在自己创建的画布上工作**。
写了用户既有画布，如实说一句：「二十秒内你就会看到；要是你有没保存的改动，顶部会出条
横幅，处理一下再继续。」——**不要**再一律叮嘱「请刷新页面」，那已经不准确了。
唯一确实要提刷新的情形：你**新建**了画布（切换器里不会自己冒出来）。
