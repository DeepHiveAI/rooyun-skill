# 视频提示词书写规范

> RooYun Skill 参考文档（从 SKILL.md 拆出）· 主文件：[SKILL.md](../SKILL.md)
> **何时读**：**所有视频生成前必读**；写 i2v/flf2v/ref2v 提示词时

## 视频提示词书写规范（所有视频生成必读）

下面这些不是文风建议，是**模型输入约定**：写错不报错、照常扣钱，问题要到出片才看得见。
白模换角与定嗓那两章只写各自的增量，公共部分全在这里。

### 五段式骨架

段序固定：**参考声明 → 音色锁定 → 画面 → 台词 → 限制**。用不到的段直接省略。

下面是一条写好的提示词——**这就是全文，逐字可抄**：

```
<Picture 1> 是林小满（相貌、服饰以它为准）。<Picture 2> 是深夜便利店。
<Audio 1> 是林小满的声音样本，音色、嗓音特征严格以 <Audio 1> 为准；语气、情绪、语速不受 <Audio 1> 约束，按台词情境自然表演。
夜戏，中近景。林小满推开便利店的玻璃门，冷白灯管在她身后闪了两下，镜头缓慢跟随。
台词：林小满（清冷女声·压着火气）：“这批货今晚必须出城。”
【限制】画面不出现字幕、文字、水印与Logo；人物长相、发型与服装全程一致
```

逐段对照：

| 段 | 内容 | 要不要写标记 |
|---|---|---|
| ① 参考声明 | 每个 `<Picture i>` 是谁 | 不写，直接是句子 |
| ② 音色锁定 | 每个 `<Audio j>` 驱动什么 | 不写，直接是句子 |
| ③ 画面 | 镜头、景别、光线、氛围、运镜 | 不写，直接是句子 |
| ④ 台词 | 谁、什么情绪、说什么 | **`台词：`**（真标签） |
| ⑤ 限制 | 本镜最容易出错的 3-8 项 | **`【限制】`**（真标签） |

⚠️ **只有 `台词：` 和 `【限制】` 这两个标记要真写进提示词**，上表里的「① 参考声明」
这类段名是本文档的讲解用语，**不要抄进去**——写进去会被模型当成画面内容。

段序有讲究：参考声明必须在**最前**（模型先建立「谁是谁」，再读画面描述），
【限制】恒在**最末**。中间三段的顺序无所谓。

### 零、提示词是模型无关的，参数不是

`<Picture i>` / `<Video k>` / `<Audio j>` 是**平台标签**，不是某家模型的语法：提交时平台按目标
模型翻译（火山 Seedance 2.0 系翻成官方的 `@图片N / @视频N / @音频N`，MiniMax H3 经服务端
改写器编成它的 Context-IR 结构）。所以**同一条提示词换模型不用重写**，也不要照着某家模型的
官方文档另写一套（比如手打 `@图片1`——能用，但混写两套只会让编号更难核对）。

换模型时会变的是**参数与参考素材**，先看 `dj models` 每条下面的「视频」行再选：

| 看什么 | 对不上会怎样 |
|---|---|
| 时长区间（如 H3 5-15s、Seedance 2.0 4-15s） | `durationSec` 越界被**静默夹取**，不报错 |
| 分辨率档（H3 只有 480p/720p，Seedance 标准版到 4k） | 不在档内的 `resolution` 回退默认档 |
| 参考视频 / 参考音频上限为 0 | 带了对应素材直接 400 `model_unsupported` |

两家的语义差异（提示词照写，但预期要对）：

- **多镜头**：Seedance 2.0 支持一条提示词内「【镜头N｜mm:ss-mm:ss】」多镜硬切（`createStoryboard`
  打包出的段就是这种）；H3 **同样照收多镜段，不会因为段里有多个构图就拒绝生成**——接口层没有
  「一段一镜」这回事。差别只在表现倾向：H3 偏向把一段当一个连续镜头理解，段内构图变化多、
  动作与对白密集时（例如 15s 内要完成 3-5 次构图切换 + 多人动作 + 大量对白），容易不切镜或漏动作。
  **所以别默认替用户拆镜**：先拿代表性的一段在 H3 上实测，切不动、漏动作再拆，拆之前的
  「必须一段一镜」是没有依据的。
- **参考视频**：两家都是动作/走位/运镜参考。白模换角章的写法目前只在 H3 真机验证过。
- **参考音频**：H3 是音色参考（定嗓章的「语气、情绪不受约束」缓解句为它而写）；Seedance 2.0
  的音频参考官方语义是声音指派，那句缓解条款在它上面未验证，不要指望同样效果。

### 一、参考声明：编号不要猜

`<Picture i>` / `<Video k>` / `<Audio j>` **三类各自独立编号，都从 1 开始**。

编号的来源分两种情况，**搞混就是主客体对调**（拿场景板当人脸、主角配角互换）：

| 你怎么给参考 | 编号 = 什么 |
|---|---|
| 自己传 `--reference` | 你上送数组的下标：`referenceAssetIds[0]` 就是 `<Picture 1>` |
| **不传，让服务端按画布边解析**（分镜卡的推荐用法） | 服务端解析出的顺序 |

第二种此前只能靠猜——顺序要等生成回执的 `meta.resolvedReferences` 才知道，
而提示词必须在提交时就写好。现在**用 `dj canvas lint` 拿确定答案**（只读、不扣积分）：

```bash
# --pretty 直接把预演打成人眼可读的一栏（体检报告末尾的「参考预演」块）
dj canvas lint "$CANVAS" --pretty
#   【参考预演｜提示词里的 <Picture i> 照抄这里的编号，顺序与提交时逐位一致】
#     镜1 推门
#         <Picture 1> = 林小满 · 设定板　[hub]
#         <Picture 2> = 深夜便利店 · 全景　[hub]

# 要拿去拼字符串就**不带 --pretty**（那时输出的才是 JSON）：
dj canvas lint "$CANVAS" | jq '.data.references[] | select(.nodeId=="'"$SHOT"'")'
```

`tag` 直接抄进提示词，`label` 就是「这张参考是谁」。顺序与真正提交时**逐位一致**
（同一个解析函数），所以不必先烧一条废单去看回执。

### 二、台词：两个前缀，别混用

站内有两条独立的台词编译路径，各有各的前缀——**看台词是怎么来的**：

| 台词来源 | 前缀 | 谁写的 |
|---|---|---|
| `createStoryboard` 落的分镜视频卡 | `音轨：` | 平台。段的 `videoPrompt` 里**已经含**这一行，你不用管 |
| 你自己写 / 改视频卡的 `prompt` | `台词：` | 你 |

**分镜链路不要自己补台词**：`analyze/storyboard` 的 `segments[].videoPrompt` 里已经有
`音轨：角色名（音色·表演）：“台词”` 了，再补一遍等于同一句话说两遍。
（注意 `segments[].audio` 是**布尔值**——「本段要不要出环境音」，不是台词文本；
`shots[].audio` 才是台词，而它早已被编译进 `videoPrompt`。两者同名不同物。）

自己写台词时照这个格式（与平台分镜产出的格式**逐字同构**，两者混在一张画布上才不打架）：

```
台词：林小满（清冷女声·压着火气）：“这批货今晚必须出城。”
```

- **角色名（音色·表演）：“台词原文”**。音色 = 声线锚（`清冷女声`、`低哑烟嗓`），
  同一角色全片**逐镜恒定**——每镜独立生成，音色写变了就换嗓；表演 = 情绪 + 发声方式
  （`压着火气`、`带哭腔`、`从压抑到爆发`），不写孤词标签；
- **引号用中文弯引号 `“ ”`，且是有语义的**：引号里的字会被识别为要对口型的**对白**。
  内心独白写 `OS：…`、环境音效写 `OV：…`，**都不加引号**——加了模型会让角色开口念出来；
- 多条用 ` / ` 分隔（`台词：A（…）：“…” / OV：雨声`），**不要合并两个人的台词**；
- 台词**一字不改**地照抄剧本——删语气词、删称呼、把对白改成 OS 都会让戏走样。

### 三、限制段

`【限制】` 后面跟 3-8 条、用 `；` 分隔。**只写当前这一镜最容易出错的那几项**——
否定词越堆越稀释，长负面清单反而降低遵从度。

`ref2v` / `i2v` / `flf2v` 三个粒度**带 `--canvas` + `--node` 提交时服务端会自动补**（见下），
那种情况一般不用自己写；不定向落卡（没有 canvas/node）就得自己写。

### 四、服务端会替你补什么（2.10.0 起）

带 `--canvas` + `--node` 提交视频生成时，服务端按画布上下文**追加**三段：

| 段 | 补的条件 |
|---|---|
| 参考声明 | 服务端解析过参考、且你**没写** `<Picture n>` |
| 台词 | 上游分镜图卡的 `sourceShot` 里有台词、且你**没写**「台词：」或「音轨：」 |
| 【限制】 | 你**没写**「【限制】」 |

三条铁律：**只追加不改写**（你写的每个字原样留在原位）、**幂等**（自己写过的段不会被补第二遍）、
补了什么在回执 `meta.promptCompile.applied` 里如实回显（没有这一位 = 一个字都没动）。

要逐字可控就传 `--params-json '{"promptCompile":"off", …}'` ——白模换角的动作锁定句、
定嗓的音色缓解条款那类场景建议关掉，多一句平台补的话都可能改变模型的取舍。

### 五、最容易犯的一条

**提示词里描述了参考视频没有的动作 = 模型听文字不听视频。** 详见白模换角章，
但它对所有带参考的生成都成立：动作的真相源只有一个，别让文字和素材打架。
