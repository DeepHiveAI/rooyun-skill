## 角色音色一致性：试镜定嗓（对白剧集必读）

**问题**：视频模型（`ref2v`）出的片自带人声，但**每次生成自行定嗓**——同一个角色在
第 3 镜和第 7 镜里是两把嗓子。这在生成时不报任何错，只有观众听得出来；一部对白剧
不锁音色，等于每一镜都在换演员。

**解法（试镜定嗓）**：先让角色「试镜」一条单人片段 → 抽出人声轨当**语音样本** →
绑到角色名上 → 此后该角色每一条对白镜头都把样本作为参考音频注入。原理是**同域样本**：
模型自己产出的音频反喂自己，音色遵从度最好——所以样本一律来自试镜片，
**不要**拿 TTS 配音、外部录音当样本（不同音色空间，遵从度差一截）。

### 五步全流程（每一步都可自动化，照抄即可）

```sh
# ① 试镜：ref2v 出一条该角色的单人片段（不带参考音频！）
#    提示词四要素：单人近景 + 环境安静无BGM + 一句剧本台词（带情绪指令）+ 详细音色描述。
#    音色描述从角色小传/形象推导（年龄/性别/音质/气质/语速），这段就是「导演要的嗓子」：
dj uuid   # → $REQ1
dj generate --request-id $REQ1 --model <ref2v模型id> --capability ref2v \
   --reference $CHAR_PORTRAIT_ASSET \
   --canvas $CANVAS --node $AUDITION_NODE \
   --params-json '{"prompt":"<Picture 1> 是主角林小满的定妆照，画面人物的相貌、服饰以 <Picture 1> 为准。单人近景固定镜头：安静室内，无背景音乐，无环境嘈杂声。林小满正面对镜头说话，口型清晰，神态从容。【音色】清亮干净的少年女声，语速轻快，尾音上扬，带一点少年气的沙哑。她说：「这批货，今晚必须出城。」","durationSec":6}'
dj task <taskId> --watch      # → 产物视频 assetId = $AUDITION_VIDEO

# ② 听音闸：把试镜片交给用户听——嗓子对不对是主观判定，必须人拍板。
#    不满意 = 换 requestId 换 seed 重出一条（改音色描述段更有效），满意才进 ③。

# ③ 抽人声轨（v2a）：dryVoice 滤掉环境音，transcribe 拿转写做质量闸
dj uuid   # → $REQ2
dj generate --request-id $REQ2 --model <v2a模型id> --capability v2a \
   --params-json "{\"video\":\"$AUDITION_VIDEO\",\"dryVoice\":true,\"transcribe\":true}"
dj task <taskId> --watch      # → 产物音频 assetId = $VOICE_SAMPLE
#    ⚠️ 查终态响应顶层的 transcript 字段：与台词逐字比对。念错词/混入了提示词片段
#    （比如把「定妆照」念了出来）= 试镜片废，回 ① 重出。transcript 缺失 = 转写服务
#    没跑成，不判失败，人工听一遍再决定。

# ④ 绑定到角色名（角色名先 GET 抄 knownCharacters，逐字一致，别手拼）
dj character-voices $CANVAS --pretty          # 看谁还没定嗓 + 抄准角色名
dj character-voices $CANVAS --bind "林小满" --sample $VOICE_SAMPLE --label "试镜样本"

# ⑤ 此后该角色**每一条**对白镜头：ref2v + --reference-audio + 提示词标签声明
dj generate --request-id <新uuid> --model <ref2v模型id> --capability ref2v \
   --reference $CHAR_PORTRAIT_ASSET --reference-audio $VOICE_SAMPLE \
   --canvas $CANVAS --node $SHOT_NODE \
   --params-json '{"prompt":"<Picture 1> 是主角林小满的定妆照，画面人物的相貌、服饰以 <Picture 1> 为准。<Audio 1> 是林小满的声音样本，音色、嗓音特征严格以 <Audio 1> 为准；语气、情绪、语速不受 <Audio 1> 约束，按台词情境自然表演。……（镜头描述与台词）","durationSec":6}'
```

### 注入提示词的两条铁律（不是风格建议，是模型输入约定）

> 标签编号、五段式骨架、台词格式这些公共规范在「视频提示词书写规范」章；
> 这里只说 `<Audio j>` 的增量。另：定嗓场景建议 `promptCompile:"off"`——
> 下面第 2 条的缓解条款需要逐字可控。

1. **必须用 `<Picture i>` / `<Audio j>` 标签逐一声明每个参考驱动什么**。编号按类型
   1-based，即上送数组的下标：`referenceAssetIds[0]` 是 `<Picture 1>`，
   `referenceAudioAssetIds[0]` 是 `<Audio 1>`。不写标签，一致性显著下降；
   参考音频到底被当「音色参考」还是「原音轨复用」**完全由这段提示词决定**。
2. **缓解条款必须写全**：「音色、嗓音特征严格以 `<Audio 1>` 为准；**语气、情绪、
   语速不受 `<Audio 1>` 约束，按台词情境自然表演**」。后半句是实测逼出来的——
   只写前半句时，样本台词的语气会把新台词的情绪拖平（怒斥的戏念得四平八稳）。
   服务端已在注入链路自动调低样本的韵律权重（保音色、放情绪），提示词条款与它
   是配合关系，**两者都要在**。

### 硬约束速查（都在计费前判定，违反 400 不扣钱）

| 约束 | 数值 | 违反后果 |
|---|---|---|
| 参考音频只有 `ref2v` 吃 | — | 挂别的能力词直接 400（别的链路不透传，放行=假锁嗓） |
| 每段时长 | **2–15 秒** | 服务端按资产真实时长核对，超界 400 |
| 段数上限 | 3 段 | 上游只有三路通道 |
| 必须伴随参考图 | ≥1 张 | `ref2v` 本就要求，照常给 |
| 容器 | 仅 wav / mp3 | 其余测不出时长，入口拒绝 |
| **样本别裁短** | 保留完整台词段（≥5s 量级） | 实测硬结论：3 秒短样本会让模型把提示词里的
参考声明念进台词（两个 seed 100% 复现）；试镜片单人单句，**整条音轨即样本，无需任何裁剪** |

### 还有三件容易做错的事

- **多时期角色各自定嗓**：`方昱(少年)` 与 `方昱(成年)` 是两个绑定键、两条试镜、
  两个样本——本来就该是两把嗓子。
- **绑定键逐字一致**：消费侧按角色名精确匹配。写错键不报错，后果是生成时**静默不注入**
  ——卡建了、片出了、钱扣了，音色没锁。所以键一律从 `dj character-voices` 的
  `knownCharacters` 里抄，别手拼。PUT 一个画布上不存在的名字会被 404
  `character_not_found` 顶回来，响应里附现有角色名单，照着改即可。
- **情绪重场戏出片后加一道对听**：参考音频对情绪表现力有轻微抑制（已在服务端调参
  压到最低但非零）。怒斥、恸哭这类强情绪镜头出片后听一耳朵，情绪没到位就换 seed
  重出——音色是锁死的，重出不会换嗓子。

### 这条流水线花多少钱

试镜片 = 一条普通 ref2v 视频的价；抽音轨按**产出秒**计价（约 0.002 积分/秒量级，
6 秒样本≈0.01 积分，几乎免费）；绑定读写不扣钱。真正的成本是试镜抽卡——
音色描述写得越具体，一次过的概率越高。
